# OpenAI visual audit / Auditoría visual de OpenAI

Fecha de consulta: 2026-08-27.

## Primer viewport observado

La página usa fondo negro y una navegación horizontal fija con logo, secciones principales, búsqueda, inicio de sesión y una acción primaria. El hero no comienza con una imagen gigante: comienza con una pregunta centrada, un campo de entrada amplio y ejemplos de uso. La interacción principal está clara antes de mostrar contenido editorial.

La pantalla mantiene mucho espacio negro. Los controles tienen bordes discretos, radios moderados y una escala contenida. El acento no está distribuido por toda la interfaz; se reserva para estados y acciones. La experiencia se siente producto antes que landing.

## Primera transición

Después del hero aparece una imagen editorial grande asociada a una noticia principal. El contenido se divide en una pieza dominante y una pieza secundaria. La jerarquía se construye por tamaño, posición y densidad de copy, no por acumulación de tarjetas.

## Noticias y contenido

La sección de noticias usa una grilla irregular con imágenes abstractas, retratos y títulos largos. Las imágenes funcionan como índices visuales. La información editorial mantiene categoría y fecha en una escala menor. Los espacios vacíos separan grupos y dejan que cada bloque respire.

## Patrones reutilizables sin copiar

1. Definir una acción o pregunta dominante en el primer viewport.
2. Usar negro como espacio de lectura, no como decoración futurista.
3. Reservar el color para diferenciar estados, categorías o acciones.
4. Presentar una pieza editorial principal y luego una grilla de contenido relacionado.
5. Hacer que video, audio o imagen expliquen un trabajo concreto; no usarlos como fondo permanente.
6. Mantener navegación y controles pequeños mientras el contenido lleva el peso visual.
7. Tratar la escala, el ritmo del scroll y la composición como parte del producto.

## Límite de referencia

Estos hallazgos son principios de composición y comportamiento. No se copian logos, textos, activos, layouts exactos, identidad ni código de OpenAI.

## Página audiovisual observada: Sora 2

La página mantiene la navegación fija y usa una composición de lectura larga. Los videos no son un fondo ornamental: cada pieza está asociada a un prompt visible y a una explicación concreta sobre control, consistencia, física o audio. El usuario puede cambiar de video mediante un rail lateral de miniaturas y activar el sonido desde un control pequeño.

La relación entre medio y texto es directa: se muestra una demostración, debajo aparece el prompt que la produjo y después el texto explica qué debe observarse. La página no intenta mostrar todos los controles al mismo tiempo. El movimiento se agrupa por escenas y la interacción sirve para elegir una variante, no para decorar.

Los patrones que se pueden reforzar en Universal Agent Workspace son:

| Patrón | Regla reutilizable |
| --- | --- |
| Video como evidencia | Cada video debe probar una capacidad o decisión; debe tener una frase de contexto. |
| Prompt visible | Mostrar la intención que produjo una visual cuando eso ayude a entenderla. |
| Rail de variaciones | Permitir cambiar escenas o estados sin llenar la pantalla de tarjetas. |
| Audio explícito | Usar play, mute y duración visibles; nunca depender del autoplay con sonido. |
| Física y continuidad | Describir trayectoria, persistencia de objetos, cámara y estado entre tomas. |
| Narrativa larga | Alternar una demostración grande con texto de lectura y dejar aire entre secciones. |
| Error realista | No prometer perfección; mostrar límites, fallos y cómo se controla el riesgo. |

La referencia no implica copiar Sora, OpenAI, sus textos, sus videos ni su identidad. Se toman decisiones de estructura, relación entre demo y explicación, controles audiovisuales y ritmo de lectura.

## Página empresarial de diseño observada

La página de soluciones para equipos de diseño usa una navegación más específica que la página institucional y mantiene una acción primaria clara en la esquina superior. El hero combina una frase grande de varias líneas con una palabra o segmento de color suave, una explicación corta y dos acciones. El fondo tiene textura ambiental muy contenida; no depende de un panel de dashboard para comunicar valor.

La narrativa baja de una promesa a resultados concretos: elegir mejores enfoques, diseñar con coherencia y detectar problemas antes. Después presenta flujos concretos como captura a prototipo, idea a prototipo, URL a prototipo y auditoría de UX. La página demuestra el trabajo con tareas reconocibles, no con una lista de capacidades abstractas.

Patrones que se añaden a la referencia:

| Patrón | Aplicación para Universal Agent Workspace |
| --- | --- |
| Promesa con una sola palabra acentuada | Usar acento para marcar el resultado, no para decorar cada bloque. |
| Tres resultados concretos | Explicar el beneficio operativo antes del catálogo de técnicas. |
| Flujos reconocibles | Mostrar cómo la skill transforma una petición real en un resultado. |
| Acción dual | Separar explorar de empezar; no mezclar lectura con ejecución. |
| Textura ambiental | Usar una textura o shader sólo como capa de profundidad, con opacidad baja. |

La referencia sigue siendo de comportamiento y composición, no de identidad o copia visual.
